## Responsibilities

The primary maintainer owns issue triage, pull request review, security
response, release management, roadmap decisions, and enforcement of repository
invariants. Contributors may help with any of these activities without being
described as maintainers until that responsibility is explicitly granted.

## Release process

1. Confirm the release scope and update `CHANGELOG.md`.
2. Run the complete verification suite from a clean checkout.
3. Merge the release pull request only after required checks pass.
4. Create an annotated `vX.Y.Z` tag on `main`.
5. Publish GitHub release notes with real features and known limitations.
6. Verify links, installation instructions, and the release artifact page.

Maintainer status is based on sustained responsibility and trust, not a single
contribution. Changes to this file require explicit maintainer approval.
